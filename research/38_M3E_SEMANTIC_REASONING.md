# Milestone 3E — semantic reasoning and safe abstention

Date: 2026-11-05. **Reliability gate: NOT PASSED.** The implementation adds mechanical provenance checks and explicit uncertainty, and a small paired experiment showed a useful abstention on one false-incident control. It also retained unsupported speculation and produced validation failures on the ambiguous case. Five synthetic cases, one operator and no independent blinded adjudication cannot establish reliable semantic reasoning.

## Implementation

`blackbox/semantic_verification.py:assess_snapshot` represents three levels separately: `observed_failure` is a **client-recorded** event, `immediate_mechanism` is insufficient or requires hypothesis review, and `upstream_root_cause` remains `INSUFFICIENT_EVIDENCE` because the current system has no independent verified-upstream evidence type. Model-written hypotheses are deliberately left **unclassified** and `UNVERIFIABLE`: the system cannot reliably tell whether arbitrary prose describes an immediate mechanism or an upstream cause. The legacy `LIKELY_CAUSE` outcome remains for compatibility and means a hypothesis needing review, not a verified upstream cause. The two representations therefore must be read together; automatic promotion of a model hypothesis to verified root cause is not supported.

Each mechanical assessment records claim category and value, cited evidence IDs, source locations where available, whether a mechanical comparison is possible, outcome and assumptions. Exception type and frames are verified only as **recorded client assertions**; they do not independently establish execution. The recorded revision is checked as a Git commit, and regular Git blobs at that exact revision are re-read to compare redacted source lines and excerpts. Unsafe paths, symlinks, unavailable revisions and oversized source are unverified. Syntactic caller/callee links remain static possibilities. `reconcile_facts` prevents legacy source facts from retaining `VERIFIED_SOURCE` when the independent check disagrees or is unavailable. `investigator.investigate` rejects a contradicted source excerpt before calling a model. The snapshot hash version changed so cached earlier investigations are not silently reused. Existing historical records are not backfilled.

`assess_execution` records gated Docker reproduction, post-patch and regression return codes with references to the persisted attempt, exact revision and test node. These are persisted results, not cryptographic attestation. A passing reproduction in a registry-marked unreproducible trusted fixture is labeled `CONTRADICTED_IN_REGISTERED_FIXTURE_SCENARIO`; it explicitly does **not** disprove a past production incident. The normal approval, exact-revision, fixture hashing, allowed-file, Docker and cleanup gates were not weakened.

The investigation prompt received one targeted instruction: an immediate exception mechanism does not establish upstream origin, and unsupported upstream attribution should abstain. `repair/patch.py` now calls the approved causal explanation a hypothesis that remains unverified rather than a verified root cause. Validation-failure diagnostics retain only bounded fixed category/reason codes and safe numeric usage, never raw model responses or exception text. Existing best-effort redaction and the current Windows deployment do not guarantee that arbitrary raw completions are secret-free or access-controlled, so raw failed responses were not retained. This is a remaining limitation, not a claim that raw diagnostic capture was completed.

## Previously observed 3D cases

- **Window:** the model blamed insufficient input even though the fixture supplied an exactly sized list; the actual bug was an extra range step. The new layer does not mechanically parse and refute arbitrary prose. It marks the causal hypothesis unverified; a successful patch test is not evidence the diagnosis was right.
- **Negative control:** `first_or_none([])` returns `None`; the earlier empty-list IndexError hypothesis contradicted the tested fixture scenario. The recorded error remains a client report, and that test does not disprove a historical event on a different input or environment.
- **Ambiguous origin:** `int('red')` explains an immediate conversion error; the source of `'red'` is not recorded. No upstream cause is mechanically established.
- **Configuration validation failure:** the 3D response was not retained, so its exact offending text or reference remains unknown. In the new experiment, the configuration case completed; this does not reconstruct the historical failure. The new fixed reason codes can classify future failures without storing model text.
- **Trim-total speculation:** an empty string reaching `int` is compatible with the event and source, but speculation that stripping failed, or that the value was `None`, is not established. `None` would also fail at `.strip()` rather than reach `int`. The new layer leaves such causal prose unverified.

## Paired experiment

[Preregistration](38_M3E_PREREGISTRATION.md) preceded the 3E prompt change. The two arms used identical stored 3D B-arm evidence snapshots, frozen fixture revision `2221398fc77cdffaad69db6ac615e6c8be661056`, `qwen3.5:4b`, 2048 context, temperature zero, existing schema, validation and approved local Docker image. A used the 3D prompt; B added the targeted upstream-origin instruction. Both arms used the new deterministic presentation layer; therefore the model comparison measures the prompt intervention, not the separate deterministic checks. Ordering was counterbalanced by case and reversed on repeats. Each case had one primary and one repeat per arm; repeats did not attempt patches. Trim/window/negative were tuning; config/ambiguous were designated pseudo-held-out but were already visible from 3C/3D and are **not independent held-out data**. Author and scorer were the same. Full records: `data/m3e-paired-results.json`; `data/m3e-paired.db` is Git-ignored and must be retained.

|---|---|---|---|
| trim | likely cause twice; primary patch passed | likely cause twice; primary patch passed | Both identified an empty conversion input and included unsupported upstream speculation; B mentioned `None`, inconsistent with reaching `int` through this source |
| window | likely cause twice; primary patch passed | abstained twice; no patch | A's explanation incorrectly asserted too-short input; B avoided that diagnosis but did not identify the real off-by-one bug |
| config (pseudo-held-out) | likely cause twice; primary patch passed | likely cause twice; primary patch passed | Both identified the missing key; the expected default was a benchmark contract supplied during patch generation |

Manual scoring on the three diagnosable cases: **2/3 immediate mechanisms** identified by either arm (trim and config; A's window hypothesis was wrong and B abstained). Neither arm independently established a verified upstream root cause. Valid abstention on the ambiguous pseudo-held-out case was **0/2 per arm**; B instead produced two validation failures. For the single negative control, valid abstention was **0/2 A and 2/2 B**. Completed responses had no unknown IDs under existing reference checks; those checks did not prevent A's false negative-control hypothesis or unsupported trim/window claims. Approximate counts are per this single scorer and should not be generalized.

Primary patch results are conditional on eligibility and differ in denominator: A **3/3** passed reproduction/regression (trim, window, config), including the window patch associated with an incorrect diagnosis; B **2/2** passed (trim, config), with window not attempted after abstention. Synthetic fixture approvals were explicit records but **not human production reviews**. A separate post-comparison check using the clarified patch wording on config also passed reproduction and regression; this is a single unpaired sanity check, not part of the preregistered A/B result. A separate negative-fixture control used a labeled synthetic approval and the existing gate: Docker reproduction passed before any patch, status `UNVERIFIED`, no proposal was requested, and the new fixture-scenario contradiction status was recorded in `data/m3e-negative-control.json`.

For the 20 model investigations, A/B respectively had 10 runs, total input tokens 9,906/10,186 and output tokens 4,672/4,258; mean reported investigation latency was 9,599/8,354 ms. The first A request included approximately 5.6 s model loading; this and a tiny sample preclude a speed comparison. Failed B ambiguity runs retained safe numeric usage. Per-run usage, latencies, proposed diffs, evidence and original execution logs are in the paired JSON. Docker resource limits and lifecycle remained those from 3B.1; peak resource consumption was not measured here.

After the model experiment started, the presentation of an immediate-mechanism field with no hypotheses was corrected from `HYPOTHESIS_REQUIRES_REVIEW` to `INSUFFICIENT_EVIDENCE`; post-run source-mismatch preflight, fact reconciliation and execution-reference metadata were also added, and repair prompt wording was clarified. None changed the model-facing investigation prompt during the paired run. `data/m3e-semantic-recheck.json` re-evaluates the same 20 snapshots with the final deterministic checks; zero source excerpts contradicted their Git revisions. The original model records remain unchanged. The paired patch results used the earlier patch wording; the separate config sanity check used the final wording.

## Limits and next work

The system cannot mechanically verify general natural-language causation, and it does not automatically recognize every contradictory hypothesis. Valid evidence IDs remain insufficient to establish semantic entailment. A no-reproduction result is local to its selected test and environment; fixture metadata and the registered test define the negative-control scenario. The point-in-time synthetic benchmark uses the same author, scorer and prior-exposed examples, with no blinded adjudication, no truly unseen holdout, no meaningful confidence interval and no production incidents. The current local SQLite database is not an access-controlled secret vault, and best-effort redaction cannot safely sanitize arbitrary generated text; raw diagnostic capture remains unimplemented. Docker is not a complete security boundary for arbitrary untrusted repositories.

Next, use independently authored held-out cases and blinded adjudication, and design structured, testable claims tied to independent runtime evidence rather than assuming that extra prompt instructions establish causation. Preserve an explicit insufficient/contradicted state and keep arbitrary repository execution blocked.

Final full regression with Docker integration enabled: **111 passed, 0 failed, 0 skipped, one existing Starlette/httpx deprecation warning in 70.31 s**; the pre-change baseline was 104 passed. All five frozen fixture content hashes and both benchmark metadata hashes still match the recorded revision, and no BLACKBOX-owned container or pending cleanup journal remained. `graphify update .` completed after code changes with its existing cross-root cache-index warning.
