# Milestone 4B failure analysis and next test

The experiment produced no evidence of improvement: all six experimental calls opted to finish without a source request, so the original fixed snapshot and final prompt were effectively unchanged. The observed failure is **tool-use feasibility/interface**, not an established failure of retrieval quality or proof that model reasoning cannot benefit from retrieval. The action schema exposed operation names, but the decision prompt gave no explicit natural-language operation descriptions or example arguments; the model's repeated statement that no observations were available is consistent with misunderstanding the interface. The snapshot also contains a standing warning about missing deployment data, which may have contributed to premature abstention. These are hypotheses; no causal ablation was run.

For the inventory fixture both arms unnecessarily abstained relative to the authored default-value spec. However, that intended contract was held in the test/label material rather than recorded runtime evidence: proving a source behavior defect from an exception alone is a different claim from proving what the contract should be. For average, both arms gave the correct immediate arithmetic mechanism, but the recorded event did not independently capture the actual input and the hypothesis did not explicitly identify the intended mean formula. Both arms abstained on the unknown origin and the negative report. There were no other primary incorrect diagnoses or model-output failures in this tiny sample. The passing patch is not evidence that the model could have selected useful missing source or that an input of length one was observed in the original incident.

## Security and coverage status

The deterministic suite exercises fixture-scoped pinned reads, source provenance, traversal/extra fields/unknown operations, invalid revisions, duplicate and total request limits, static caller and callee entry points, mocked symlink-object denial, provider timeout and existing repair security gates. Docker audit and proof used the existing pinned image, explicit fixture-level approval, disposable materialization, pre/post reproduction, regression, and lifecycle manager. Working copies of all four new fixtures still match their frozen hashes; no containers or pending journal remained at the check. These observations do not prove safety against hostile arbitrary repositories; those remain disallowed.

Not yet verified: a hard end-to-end time deadline and cancellation during a blocked provider/tool operation; exact aggregate token metering; realistic hostile prompt-injection resistance; adversarial Git object and symlink integration beyond the mocked denial; comprehensive cyclic-relationship accuracy; unknown secret redaction; final hardened controller behavior with live model; and independent or blinded scoring. The decision trace is returned and saved by the evaluation script, not transactionally recorded for every aborted process. Existing provider timeout is an HTTP inactivity timeout, not an absolute wall clock. The source-scope and identity hardening added after the live comparison is a separate iteration, not included in the live results. No production route was enabled.

## Most informative next test

Do not expand agent autonomy. First preregister a separate small, synthetic tool-use feasibility test with independently specified observations, explicit descriptions of the exact two permitted read operations, unchanged security caps, an equally budgeted no-read control, and negative tests for malicious source instructions. Freeze fresh cases and prompts before model calls. Only if the model reliably requests a relevant authorized observation should a larger independently reviewed 18-case causal accuracy study be considered. This follow-up tests the interface explanation; it does not retroactively change the present result or justify a stronger capability claim.

## UNDERSTAND WHAT WE JUST BUILT

An AI agent is a model in a loop with a program that can act on permitted requests. Here the model cannot operate the computer. A **tool call** is just structured data, for example `{"action":"find_symbol","symbol":"average","reason":"locate the function"}`. `Request` checks its type and arguments; `Dispatcher.dispatch` decides whether the operation is allowed. A request to execute a command or access `../secret` is rejected. The experiment stopped before asking for either: every decision was `finish`.

The existing `collect` function starts with the recorded error and nearby source. The experimental controller may add a small source range from a registered fixture. A full Git commit identifies the immutable historical tree, so `Dispatcher._blob` reads the object at that revision rather than trusting today's working file. `semantic_verification._check_source` checks the excerpt against that same revision. A matched source excerpt shows what the code says, not which branch ran or why a caller supplied a value. The model's explanation remains a hypothesis.

In an A/B experiment, each case gets a control A and experimental B; keeping initial evidence and model equal helps isolate the effect being studied. Here B had an extra decision call but never used retrieval, and the two arms reached the same outcomes. Thus this experiment measures an interface failure and gives no reliable estimate of what useful extra source would do. A passing patch test is also limited: our average patch passes the two registered test nodes, but those tests do not cover every input or prove the historical incident's cause. The four cases, single author, absent independent review, untested hostile content and deadline gap prevent general claims about real applications.
