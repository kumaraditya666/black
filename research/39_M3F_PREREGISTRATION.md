# Milestone 3F preregistration

Written before the M3F model-facing retry change and before model access to new M3F fixtures. Compare baseline A (existing 3E model call and validator, reference retry disabled) against B (at most one additional provider call after the specific missing-required-reference validation error, with a fixed explanation and the same evidence; the fresh response must pass the unchanged schema and citation checks). Do not retry malformed JSON, unsupported IDs, truncated output, provider errors or source-integrity errors. Do not synthesize citations, convert malformed output into abstention, or execute model-generated commands. Both arms use the same deterministic source verification and bounded claim presentation; the experiment tests the retry policy, not a second LLM adjudicator.

Freeze new trusted cases, source, expected outcomes, metadata and hashes in a separate Git revision before any M3F evaluation call. The known 3C ambiguity case is a tuning case; the new M3F cases are evaluation cases but have the same author and scorer and no blinded or independent reviewer, so describe them as newly authored and unblinded, not independently adjudicated. Use exact frozen events and snapshots in both arms, 4B model, 2048 context, same schemas and temperature. Counterbalance A/B order by case and reverse it on the repeat. One primary and one repeat per arm per case; no auto-repairs in this diagnostic evaluation. Measure immediate mechanism, upstream attribution, abstention, invalid outputs, contradictions/unsupported claims, citation validity, model calls, aggregate token usage and latency; report every failure and retry. Docker executes only the pinned trusted reproduction tests before model evaluation; stop on a security block. A negative incident report is deliberately false and cannot represent production truth. No benchmark file, expected label or prompt will be changed in response to model outputs.

## Final validation iteration (registered after exploratory run, before this iteration)

A post-run code review found that legacy normalization could fill an otherwise incomplete abstention from recorded data, contrary to the requirement that malformed provider output not become successful abstention. The final implementation requires an explicit reported failure referencing the recorded event, an explicit empty hypotheses list and nonempty missing-evidence list before normalization. No fixture, frozen event or model prompt is changed. Run a separate fresh paired primary-only iteration on the same five frozen evaluation cases and the known ambiguous tuning case: A disables strict raw-abstention checking and reference retry to reconstruct the previous path; B enables both. Alternate A/B order; use the exact prior stored snapshots. This is a separately disclosed validation iteration, not additional independent held-out evidence. Keep the initial pre-registered repeated run and do not merge its outcomes with this iteration. Retry usage accounting is also corrected for a provider error on the second call.
