# Milestone 4B: bounded retrieval experiment

Preregistered before live 4B model evaluation. The control is the existing fixed snapshot and investigator; the experimental arm starts with the identical snapshot and asks the same local model for up to two read-only observations before the same final Findings schema and validations. No repair approval follows from a read. The existing one-reference retry in the baseline is retained; the experimental arm must include any final retry within its three-turn limit.

The 4A handoff specifies two operations while the 4B prompt lists four candidates: implement `find_symbol` and `read_source` first; callers and callees remain bounded static search variants, not new authority. Limits are two requests, 20 lines and 1,200 characters per read, 2,000 source characters total, and three model calls including the conclusion. Each request has an immutable revision and authorized fixture paths supplied by the controller. A failed lookup, unavailable revision, oversized result or context overflow is recorded, never silently truncated. Content is untrusted and redaction is best effort. A source match proves neither execution nor cause.

Evaluation is paired by case and counterbalanced. Use frozen, newly authored synthetic cases where possible, with preregistered expected mechanism, upstream attribution, ambiguity and required evidence; repeat cases without selecting a best repeat. Track each arm's outcome, factual attribution, abstention, unsupported claims, lookup relevance, invalid schema, input/output tokens and end-to-end time. Treat failed or missing observations as failures, never abstentions. Report individual cases and denominators, separate passing tests from causal correctness. More inference calls are a confound; if a matched non-tool control is not feasible, say so. Author and scorer are unblinded unless an independent reviewer is actually available.

The provisional 4A gate requires all security/provenance checks, at least two paired causal/appropriate-abstention improvements, no more than one regression, and no new false certainty on ambiguous or negative controls. Without independent labels and sufficient held-out cases, the reliability gate remains open even if the small exploratory results look favorable. Abort affected runs on source identity or Docker isolation failures. Preserve fixture-level approval, pinned hashes, approved edit paths, reproduction before patch, regression after patch and container cleanup.

## Implemented interface and limits

`blackbox/agent_retrieval.py` provides a separate, evaluation-only `investigate_with_retrieval` entry point; no current production route invokes it. `Request` is a strict Pydantic object: `action` is `find_symbol`, `read_source`, `find_callers`, `find_callees`, or `finish`; `reason` is 1–180 characters. `find_symbol` requires only `symbol`; `read_source` requires `path`, integer `start`, integer `end`; each relationship lookup requires `symbol`, `path`, integer `start`; `finish` accepts no such fields. All extra fields are forbidden. The Git revision and repository are controller inputs, not model parameters. The last two operations use the existing static retriever as scoped variants of symbol lookup; they do not add calls, authority, or execution tools.

`Dispatcher` checks local project identity, registered fixture approval and all pinned hashes, limits scope to registered non-test Python files, and checks each requested object is a regular Git blob at the full immutable event commit. Read output carries a deterministic ID, revision, path, line range, redacted exact text, request reason, `VERIFIED_SOURCE` provenance and a warning that source is not execution or cause. `semantic_verification._check_source` rechecks it; `investigate` applies the existing Findings, citation and semantic checks, records the augmented evidence and retains repair gates. Static lookup output is explicitly a possibility. Invalid requests, duplicate calls and exceeded ranges fail closed. The separate returned trace records actions and results; it is stored in the evaluation artifact, not in a new durable production audit log.

At most two decision calls and three total model calls are allowed; `_FinalProvider` prevents the ordinary reference retry from exceeding the latter. A decision request is limited to 320 output tokens; the existing final provider caps output at 768 and checks its estimated prompt plus reserve against a 2,048-token context, with `truncate=false` and `shift=false`. This is at most three 2,048-token context windows, not a separate exact aggregate-token meter. Git commands have existing per-command timeouts and the controller checks a 360-second elapsed budget between calls; the existing HTTP timeout is capped at 120 seconds after post-evaluation hardening. **There is no hard absolute wall-clock cancellation across a long tool scan or repeated HTTP read activity**, so the requested strict total time guarantee is not verified. Do not enable this interface as a production agent until an enforceable deadline and complete cancellation are added and tested. Redaction is best effort; source is untrusted, and unknown secrets or prompt injection are not proven safe.

The paired iteration ran against the initial implementation. After the model runs, controller entry was hardened to bind the supplied snapshot's incident ID, event ID and revision to the stored event, bind the fixture frame, and enforce the 2,048 context and 120-second provider timeout configuration. This is a separate post-evaluation security change; decision schema and prompt were not tuned, and the final hardened version was not independently reevaluated with the live model. Unit/regression tests cover the changed code. This distinction prevents the measured run from being misrepresented as a live evaluation of a later implementation.
