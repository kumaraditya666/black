# Milestone 4B.3 — prior failure classification

## Question

Why did the ordinary investigator abstain after the M4B.2 oracle excerpt, and which stage prevents a useful supported code mechanism from reaching the user?

## Observations

1. The ordinary final investigator's prompt explicitly says: “Do not put arithmetic inference in observed_facts: put it in a hypothesis instead,” and “An immediate exception mechanism does not establish its upstream origin. If the upstream cause is not supported, return INSUFFICIENT_EVIDENCE.”
2. The existing schema can syntactically encode cited facts and hypotheses, but has no typed field that says “this mechanism follows from pinned source; incident attribution is not established.”
3. `Findings.validate_claims` forces `INSUFFICIENT_EVIDENCE` and an empty `hypotheses` list to coexist. `validate` also forces every `LIKELY_CAUSE` primary hypothesis to cite the event and a resolved stack frame. Since event text is a client report, neither check independently verifies that the code executed.
4. `investigate` replaces model-authored `observed_facts` with `[]` before returning/persisting findings. Therefore even correctly cited source observations produced by a model do not appear in that field of the final ordinary result. Deterministic `atomic_claims` remain, but are generated by `extract_facts` and are not the same as a model's semantic mechanism explanation.
5. `semantic_verification._check_source` can establish that a source excerpt matches a pinned regular Git blob. `assess_snapshot` labels source and event provenance, but also records that the event report does not establish execution and that static source/relationships do not establish runtime execution. `review_hypotheses` classifies model prose as `UNCLASSIFIED_CAUSAL_HYPOTHESIS` and `QUALIFIED_REQUIRES_REVIEW`; no semantic or causal proof is computed.
6. `collect` includes recorded exception/message, stack frames, limited static callers and bounded source excerpts. It does not provide actual argument values, selected runtime branch, or deployment-specific execution telemetry unless those were separately recorded.
7. M4B.2's 16 paired ordinary outputs all validated yet abstained. The separate compact probe correctly described the local mechanism in five cases but made one false assertion that execution was established. This shows local mechanism explanation is possible in a reduced prompt; it does not establish that prompt wording alone caused the difference.

## Hypotheses (not observations)

- **Prompt contributes:** the instruction to abstain when upstream origin is unsupported may be interpreted as suppressing even a source-local mechanism, despite that mechanism being independently discussable.
- **Schema/return path contributes:** there is no typed representation for a useful mechanism with unestablished causality, and the ordinary return path removes model-authored observed facts.
- **Evidence remains insufficient for causal attribution:** missing runtime inputs and branch execution prevent linking a possible mechanism to the reported event. This is a valid causal abstention, not a reason to suppress all static facts.
- **Model capacity is not ruled out:** the compact probe was small and its prompt and output schema differed from M4B.2; one answer confused source behavior with execution evidence.

## Classification target

The factorial experiment will determine whether the clearer layered prompt, the additive layered schema, or their combination changes each separate output dimension. A change in useful static fact reporting with `NOT_ESTABLISHED` causal attribution is an improvement in information separation, not a verified-root-cause accuracy gain. Any unsupported runtime, contract, or causal claim is scored separately. M4B.2 is reused only as background diagnosis; all four arms run on the separately frozen six-case confirmation set.
