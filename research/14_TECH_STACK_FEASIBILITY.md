# Technology feasibility and costs

Reviewed 2026-11-04. Quotas and terms change; recheck before launch. CONFIRMED claims are cited; architecture judgments are INFERRED. No accounts were created or services purchased.

| Layer | Options and practical assessment | Free boundary / risk |
|---|---|---|
| UI | Next.js, Tailwind and Motion can build accessible views; prefer HTML/SVG for evidence and dependency graphs. Three.js/R3F optional only if user testing demonstrates value. | Local development is free; hosting, accessibility work and hardware are not automatically free. [Next.js](https://nextjs.org/docs), [Tailwind](https://tailwindcss.com/docs), [Three.js](https://threejs.org/). |
| API and jobs | FastAPI plus a local Python worker makes testable durable boundaries; store job states in database. Serverless can accept webhooks but long investigations need durable orchestration, timeout and retry design. | Free functions have hard execution, storage and quota constraints; neither scheduler nor resident workers are guaranteed. [FastAPI](https://fastapi.tiangolo.com/). |
| Storage | Start SQLite locally; Postgres when multi-user or hosted. Full-text and symbol search before evaluating pgvector or hosted vector service. | [Supabase Free](https://supabase.com/pricing) lists 500 MB database and shared CPU; free plan constraints, pauses, egress and data sensitivity require review. |
| Telemetry | OpenTelemetry SDK/collector protocol, then bounded local storage; Loki is an optional log backend, not required for a first fixture. | Self-hosted components require disk, compute, retention and operations even where software is free. [OpenTelemetry](https://opentelemetry.io/docs/), [Loki](https://grafana.com/docs/loki/latest/). |
| Inference | Allow bring-your-own-key, explicit spending limits and a local model if capable hardware exists; route by evidence/task after evaluation. | No assumed permanent free API allowance; local inference has power, hardware and quality costs. Never silently send private source to third parties. |
| Tests | pytest and Playwright can reproduce controlled scenarios; GitHub Actions can run approved CI. | [GitHub](https://docs.github.com/en/actions/concepts/billing-and-usage) distinguishes public/private and runner types; free quotas are not isolation guarantees. Run untrusted code in a separately isolated, resource-limited environment. |
| Hosting/integrations | User-operated local process can receive local events; hosted webhook receiver requires a reachable deployment. GitHub installation tokens should be scoped per repository; Vercel/Supabase integrations optional. | [Vercel Hobby](https://vercel.com/docs/plans/hobby) is personal, non-commercial; cannot be assumed suitable for a commercial launch. Public webhook, continuous operation, backups and outbound AI create recurring costs. |

**UNKNOWN:** Reliable free AI API quotas, commercial eligibility across services, local-model adequacy for the selected hardware, persistent worker eligibility and actual per-incident cost. Estimate from measured event volume, bytes retained, tokens, compute seconds and retries, with safety caps and disable-on-limit behavior. A vector database is not a prerequisite for evidence-grounded debugging.
