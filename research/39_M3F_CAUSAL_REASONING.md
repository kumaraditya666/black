# Milestone 3F — evidence-grounded causal reasoning

Date: 2026-11-05. **Reliability gate: NOT PASSED.** A narrowly scoped recovery path and provenance review were implemented and tested, but the new unblinded benchmark did not naturally trigger the original reference error or demonstrate improved causal accuracy. No independently authored or blinded assessment was available.

## Baseline and diagnosis of the 3E failure

Before changes, the complete suite with Docker integration enabled produced **111 passed, one existing Starlette/httpx deprecation warning in 70.11 s**. The 3E stored diagnostics identified `MISSING_REQUIRED_REFERENCE`. In `blackbox/investigator.py:validate`, that exact error is raised for a `LIKELY_CAUSE` hypothesis that does not cite both the event and a resolved stack frame. JSON/schema parsing and unknown-ID validation are reached first, so the recorded error indicates a structurally parsed likely-cause response missing at least one required kind of reference; it was not a successfully validated abstention or a recorded truncation. Raw output was deliberately not retained, so whether the event reference or frame reference was missing cannot be reconstructed. A separate 3C tuning replay, summarized without raw response in `data/m3f-ambiguous-structure.json`, produced a valid likely-cause response with both reference types; this does not reconstruct the original response and illustrates session variability.

A valid explicit `INSUFFICIENT_EVIDENCE` response has no primary hypotheses and need not invent a causal hypothesis or citations beyond its recorded observed failure. Model-supplied alternatives remain subject to the existing reference validation. No malformed response is automatically converted to an abstention by the new path.

## Changes

`blackbox/investigator.py` now permits **one** fresh provider call only when a parsed likely-cause response hits the exact missing-required-event-or-frame validation error. The retry receives the same evidence and a fixed notice describing the missing reference types; it does not receive the previous raw response, and no reference is fabricated. It may return either a valid cited hypothesis or a valid abstention, but the fresh response must pass the unchanged schema, source preflight and evidence checks. Unknown IDs, schema/JSON failures, truncation, source contradictions and provider failures do not trigger this retry. Failed second responses remain failures. `reference_retry` records whether the retry occurred; numeric token usage is aggregated across calls, including a reported truncation on the second call. There is no general agent loop or execution of model-generated commands.

The legacy normalization helper could synthesize required fields for an almost-empty abstention. The final validation path now requires an explicit recorded-failure reference, an explicit empty hypothesis list, and a nonempty missing-evidence list before an abstention can complete. This preserves valid uncertainty without treating incomplete provider output as success. Existing normalization remains available for its original direct callers; actual provider output passes the stricter check by default. The snapshot version was bumped to prevent silent reuse of cached earlier outcomes.

`blackbox/semantic_verification.py:review_hypotheses` adds bounded structured review records: up to three model hypotheses, their cited IDs, source-identity checks, a `QUALIFIED_REQUIRES_REVIEW` decision, missing evidence and suggested verification steps. It reuses the existing bounded revision-pinned retrieval and source verification; it does **not** semantically prove generic causal prose, retrieve arbitrary new evidence on demand, or run suggested commands. Recorded errors, mechanical source facts, unclassified immediate/upstream hypotheses and unknown upstream cause remain separate in `reasoning_levels`. Contradicted source snapshots fail closed before a model call. Existing explicit approvals, fixture hash and revision checks, patch-file limits, Docker isolation and lifecycle cleanup were unchanged.

## Controlled comparison and interpretation

The initial preregistered paired run used the same frozen evidence snapshots, `qwen3.5:4b`, 2048 context, temperature zero, schema and validator. A disabled the reference retry; B enabled it. Order was counterbalanced and each case was repeated once per arm. Both arms used the new deterministic review records. Results: `data/m3f-paired-results.json`; copied `data/m3f-paired.db` is Git-ignored. All 24 investigations, including the four tuning runs, completed with no invalid reference IDs and **zero natural retries**. Both arms produced the same outcome for every case. On the three new cases labeled diagnosable, each arm identified the immediate cause in **1/3** and abstained on two. Both abstained on the one new unknown-origin and one new false-report control. No upstream cause was independently verified. These five examples cannot demonstrate a causal accuracy or abstention improvement.

After that run, code review identified the incomplete-abstention normalization gap described above. Before further model calls, the preregistration was amended to describe a **separate** primary-only A/B validation iteration: A disabled both the new strict raw-abstention check and retry, B enabled both, with the same snapshots and counterbalanced order. No benchmark or prompt was changed. `data/m3f-final-results.json` records 12 investigations, including the tuning case. Again every A/B outcome matched, no invalid outputs or natural retries occurred, and no reference-ID errors were accepted. This second iteration is not independent holdout evidence or a controlled estimate of the retry's effect on its target error because the target error did not occur.

A separate, explicitly labeled fault-injection sanity check (`data/m3f-injected-retry.json`) removed the event reference from the first **real local model response** in the test harness. The retry made a second actual model call, and its independently validated fresh response abstained. Two calls used 2,115 input and 805 output tokens. The first error was intentionally injected; it is not counted as a naturally occurring benchmark result. Unit tests also check a valid abstention, missing references, unknown IDs, malformed retry, provider truncation, bounded retries and preserved token accounting.

In the repeated paired run, A/B each had 12 investigations, mean reported latency **7,436/7,447 ms**, input tokens **11,700/11,700**, and output tokens **4,618/4,618**. In the separate final primary-only run, each arm had six investigations, mean latency **7,361/7,306 ms**, input tokens **5,850/5,850** and output tokens **2,309/2,309**. These are measured request usage and wall times in one session, not meaningful estimates of speed, cost or model variability. Per-run values and the exact order are in the JSON artifacts. No patches were generated in the M3F diagnostic benchmark; the existing Proof-of-Fix tests remain the regression evidence for that subsystem.

## Remaining risks and next work

Causal explanations remain natural-language hypotheses and can be wrong despite valid citations. The bounded review checks provenance, not semantic entailment; it never automatically verifies upstream causation. The legacy `LIKELY_CAUSE` field can still be read too strongly unless its `reasoning_levels` and review status are shown alongside it. The new retry can increase latency and token use and may still fail; a successful fresh response is not proof that its hypothesis is correct. Raw failed model text remains unretained because secret-safe redaction and Windows access control are not guaranteed. The 3F evaluation is tiny, synthetic, unblinded and single-author, and one tuning case had prior exposure. It does not validate production diagnosis or establish an improvement. Docker and approval controls were not broadened to untrusted repositories.

Another reasoning iteration is justified, but it should begin with independently authored, blinded held-out cases and independently captured runtime evidence, including examples that naturally exercise reference failures. Compare bounded hypothesis checks against the same evidence and measure false certainty as well as abstention; do not tune only for more diagnoses or treat passing patch tests as causal proof.
